# QA production parity

Inventory of production capabilities that need a QA equivalent. QA operating instructions: [docs/qa-environment.md](qa-environment.md); verification environment selection: [docs/testing.md](testing.md); parity stance and definition: [docs/qa-environment-parity.md](qa-environment-parity.md).

Status values:

- `parity`: QA has a documented equivalent and a verification path.
- `partial`: QA has some support, but a known gap prevents full confidence.
- `missing`: prod capability has no documented QA equivalent.
- `intentionally-prod-only`: no QA parity planned; requires explicit rationale.

## How to maintain this file

- Add new integrations in the same PR as `INTEGRATION_REGISTRY` changes.
- Status changes must cite a doc, test, smoke command, or known follow-up in the verification column.
- Missing verification means status cannot be `parity`.
- Every `partial`, `missing`, or `intentionally-prod-only` row must name its next action or rationale.
- Keep rows compact; move operational detail to the relevant topic doc and link it here.
