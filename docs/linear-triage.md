# Linear Triage

Use Backlog and Todo as two different commitments, not as priority labels.

## Buckets

- **Backlog** is the capture bucket. Use it for uncommitted work: audit findings, someday ideas, tickets that need scoping, or anything not intended for the current or next cycle.
- **Todo** is the short next-up queue. Use it only when the ticket is scoped enough to start with no further decisions and intended for the current or next cycle.

## Promotion Rule

Move a ticket from Backlog to Todo only when both checks pass:

1. **Ready:** could someone start the work with no more product, design, technical, or ownership decisions?
2. **Near-term:** is the work intended for the current or next cycle?

If either answer is no, keep the ticket in Backlog. If either answer is unclear, flag it instead of guessing.

## Priority

Priority is an input, not the decision. A high-priority ticket that is vague or not committed stays in Backlog until it is scoped and near-term. A lower-priority ticket can be in Todo when it is ready and actually next up.

## What This Does Not Do

Backlog and Todo triage only decides whether open work is captured or next up. Closing, canceling, deduplicating, or marking work done is a separate review.

## New Ticket Checklist

When creating or re-triaging a ticket, apply the Promotion Rule above. If either answer is unclear, add a short note to the ticket instead of guessing.
