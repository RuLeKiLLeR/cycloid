# Lifecycle FSM — the coordination spine

The **session lifecycle FSM** (ARC-1330) is the source of truth for where a session/PR is in its lifecycle and what happens next after a PR is opened. It replaces the scattered, per-signal decision paths of the old review loop with **one pure reducer over one D1 record per session**. The design goal — "the spine" — is that every lifecycle surface (session status, PR labels, PR-body stage, `cycloid_done`) is a **pure projection of that one record**, so views cannot drift from state.

That end-state is being rolled out slice by slice. **Read [§ Current live scope](#current-live-scope) before assuming a surface already reads from the FSM** — as of Wave 11 (2026-07-02) labels, PR-body stage, and the mirror columns are projection-sourced, but the UI status surfaces are still legacy-sourced until D-59.

> This is repo-specific architecture, not a rollout knob. The design excepted the "no phased rollouts" invariant for this one migration: the cutover was shadowed + divergence-gated (design §16), but that scaffolding is now removed — the FSM is unconditionally the single coordination authority for every post-PR session.

## The rules (read first)

1. **The FSM record is the source of truth for post-publish lifecycle state.** It lives in D1 `pr_coordination`, keyed `session_id`, one row per session.
2. **Transition writes ride the single writer.** Every field mutation from a transition goes through `applyEvent`'s versioned CAS (`UPDATE … SET …, version = version + 1 WHERE session_id = ? AND version = ?`). The only writers outside `applyEvent` are the **genesis seed** (`insertGenesisRecord`) and **backfill / version-0 maintenance** (which create or rebaseline a `version = 0` row and never drive a transition — see [Persistence, backfill, divergence](#persistence-backfill-divergence) below). Don't add any other direct writer to `pr_coordination`.
3. **Don't add a parallel decision path.** To make the lifecycle react to a new signal, add/extend a **producer** that translates it into an FSM event and let `applyEvent` decide — don't add a second code path that mutates lifecycle state or fires side-effects on its own. This is the coordination discipline the live cutover already enforces post-publish.
4. **Surfaces derive from `project(record)` — but check what's wired.** The single pure `project()` projection is the designed source for status/labels/stage/done. During the cutover most display surfaces still render from legacy fields (see [§ Current live scope](#current-live-scope)); don't hand-roll a new projection — extend `project()` and migrate the surface onto it.
5. **Don't confuse it with `session/lifecycle/`.** That directory is the older per-session DO **storage-state** reducer (runtime status/deadlines). The ARC-1330 FSM is `session/fsm/`. Different machine, different job.

## Unconditionally live (no `FSM_MODE` gate)

The `FSM_MODE` kill-switch and the shadow/off arms are **removed** (D-60, 2026-07-03 — ARC-1330's terminal sweep). The spine is unconditionally the authoritative post-publish coordinator: `applyEvent`'s side-effect sink is real, the legacy decision paths it replaced stand down, and there is no observe-only/no-op mode. Reversal is `git revert` + a forward migration, not a flag flip. The shadow-rollout divergence samplers (`divergence.ts` + the steady-state / dormant / genesis samplers) and the `arcanist.fsm.divergence` metric/monitor were removed with the switch; the permanent post-flip soak signals are the W11-G1/G4 instruments (`fsm_transition`, `fsm_stage_dwell`, `fsm.sideeffect.*`, `arcanist.fsm.parity` via `parity-check.ts`).

Production and QA both run the spine live (prod: flip commit `d9876021e`, ARC-1330 Wave 10). The Section-G deletion wave (D-50…D-60) is complete.

## The model

Kinds: initial / active / wait / `contract` (externally-owned agent) / terminal. The 17 coded states (`FSM_STATES`):

`CREATED → PROVISIONING → GENERATING (⇄ AWAITING_INPUT) → FINALIZING → PUBLISHING → REVIEW ⇄ VERIFYING → MERGE_READY`, plus terminals `ANSWERED_NO_PR`, `NEEDS_YOU`, `FAILED`, `STOPPED`, `MERGED`, `CLOSED`, `SUPERSEDED`, `ARCHIVED`.

Plan approval uses producer events only: a gated plan terminal suppresses `prompt.terminal`, then emits `prompt.awaiting_input` after the pending plan commits; Discuss and Accept emit `user.input`. Alarm/wake reconciliation repeats the event when authoritative `session_plans` disagrees with the spine. Deadline production fails closed while a plan is pending, so no destructive FSM deadline can tear down a parked session.

- **`REVIEW`** is the combined CI-fix + code-review + QA-finding convergence core (the two old review states are already collapsed into one).
- **`VERIFYING`** is **drain-only** (ARC-1330 CI-ladder cut): QA is no longer a merge gate. The verifier child is spawned at publish and runs off-gate in parallel; the `caught_up` cascade is a pure CI ladder and never routes into `VERIFYING`. The state is retained only so sessions already parked there (and any legacy re-entry) drain out — the automatic cascade adds no new entering edge, and the STOPPED→VERIFYING resume redispatch is deleted. It remains a `contract` state: a black-box verifier child runs the app @head and emits exactly one run-scoped terminal verdict, recorded as bookkeeping. (The design calls this **`QA`**; the code keeps the existing **`verification`/`VERIFYING`** vocabulary — grep `verification`/`VERIFYING`, not `qa`.) **Manual QA is the exception:** a user-initiated `verification.requested` (the PR "Verify"/"QA Test PR" button, via `requestCoordinatedVerification`) still enters `VERIFYING` from `REVIEW`/`MERGE_READY`, and a **forced** request (`event.force`, set only by the manual button) while already `VERIFYING` **supersedes** the in-flight verifier — `kill_verification(active)` + `request_verification` (burns a run, mints a fresh run id) so each click starts a new verifier rather than reusing the running one. The forced supersede returns no `spawn_verification_child` (the coordinator owns the respawn, like the `REVIEW → VERIFYING` dispatch) and is still bounded by `verification_run_count`: past the cap it fails closed to `NEEDS_YOU(verification_run_limit)`. A non-forced `verification.requested` while `VERIFYING` stays unhandled (the coordinator returns the running verifier as a duplicate).
- **`SUPERSEDED`** is the neutral benign-publish terminal (ARC-1389), added after the core design — the reason the code has 17 states where an earlier design draft counted 16.
- **`MERGE_READY` has exactly one _entering_ edge:** the `ci_green ∧ no_inflight_epoch` rung of the `REVIEW.caught_up` cascade (`transition.ts`). QA never transitions to `MERGE_READY` — verification is off-gate. The cascade is a **pure CI ladder** (verification pass/fresh no longer read):

  ```
  ci_red   ∧ under_ci_fix_cap  → REVIEW      / dispatch_epoch(ci_fix), inc_ci_fix_rounds
  ci_red   ∧ ¬under_ci_fix_cap → NEEDS_YOU(ci_fix_exhausted) / loud
  ci_pending                   → REVIEW      / WAIT (the §10 review-stuck backstop owns it)
  ci_green ∧ no_inflight_epoch → MERGE_READY / reset_ci_fix_rounds, emit_settle
  ci_green ∧ ¬no_inflight      → REVIEW      / WAIT (W11-T1 stale-green)
  ```

  The `caught_up` producer gate deliberately **excludes** `ci_green` (CI is evaluated downstream in the cascade); `ci_green` is a **live read** of the head's CI (`green`/`absent` count green — never a stored field). The cascade is **ordered, total, and fails safe** — a missing `ci` bucket reads `ci_pending` (wait) and a missing `no_inflight` reads false (wait), never toward a false `MERGE_READY`. `auto_verify_disabled` (the per-user/session QA opt-out, #6395 — and since migration `0242` the `auto_verify_enabled` default flipped **off**, so QA is opt-in for new users) no longer changes the merge decision — QA is not a gate for any cohort — it only governs whether the verifier child spawns at publish at all.

- **Two loud terminals:** `NEEDS_YOU` (needs a human; carries a closed-enum `blocked_reason`) and `FAILED` (pre-publish infra/agent failure; carries `failure_reason`). Both re-openable.
- **User-stop aborts are quiet:** `prompt.terminal{error}` carries the reducer's `errorCode` plus the DO's `stoppedByUser` corroboration (the bridge's deliberate stop-abort reason — bridge `"aborted"` alone is overloaded by classifyError text-matches/external deletes and stays a loud failure). A corroborated stop routes to `STOPPED(user)` with the `user.stop` close-out shape — never `FAILED(codegen_error)`, never loud. `STOPPED` recovers on the next `prompt.enqueued` (re-prompt recovery, mirroring the `FAILED` ARC-1470 edge), pre_stop_state-aware: post-publish stops (`REVIEW`/`VERIFYING`) re-enter `REVIEW`, pre-publish stops re-enter `GENERATING`.
- **Caps, not loops:** `ci_fix_rounds` (consecutive CI-fix rounds) trips to `NEEDS_YOU(ci_fix_exhausted)`; a lifetime `merge_ready_reopen_count` bounds CI-flap re-opens. `verification_run_count` bounds QA reruns, but because QA is off-gate a cap hit / infra failure emits a **non-blocking** `notify_qa_issue` DM rather than blocking the PR (the old `NEEDS_YOU(verification_run_limit|verification_stopped)` exits fire only for sessions draining out of the legacy `VERIFYING` gate). Never an unbounded loop.
- **Every review-loop epoch terminal MUST clear `in_flight_epoch_id`.** `caught_up` requires `no_inflight_epoch = (in_flight_epoch_id == null)`, so an epoch that finalizes without emitting a spine `epoch.*` terminal strands the marker and wedges `REVIEW` forever (ARC-1330). The terminals: `epoch.committed`/`replied`/`declined` (an agent action, with a disposition), `epoch.blocked{owner_approval | response_failed}` (→ `NEEDS_YOU`; `response_failed` = a fix/reply POST that failed past its retry cap, or a runtime that died unrecoverably mid-response; both block immediately rather than lease-reclaim), and **`epoch.settled`** — the no-actionable-work terminal (a bot-wait fallback drain, or a benign/CI-cap block) that clears the marker **only** (no disposition/head/owner write) so the cascade re-derives the outcome. Emitted at settle time from the sweep's `completed_noop` + block sites; a `*/5`-cron self-heal (`reconcileStrandedTerminalEpochMarkers`) un-strands any pre-fix standing stock.

The full state → phase/label/stage projection table is design **§12**.

## Source of truth and projections

`project(record): Projection` (`project.ts`) is **pure and total**: it reads only typed record fields — `(state, verdict, blocked_reason, prompt_intends_change, …)`, never `state` alone — and returns five derived surfaces, each via its own exposed, `tsc`-total sub-function keyed over the 17-state union:

| Projection field | Derives                                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `phase`          | `phaseOf(state)` — the canonical session phase (`VERIFYING → review_listening`; no new phase member)     |
| `feChip`         | `feChipOf(state)` — the sidebar status pill (server-side mirror of the FE's client-side `flattenStatus`) |
| `labels`         | `labelsOf(record)` — GitHub PR labels                                                                    |
| `stageSection`   | `stageOf(record)` — the PR-body / timeline stage copy                                                    |
| `cycloidDone`    | `cycloidDoneOf(state, blocked_reason)` — the post-PR done aggregate                                      |

Because there is one writer and one projection function, the illegal states the old world allowed become unrepresentable (e.g. "label says done but verdict says app-breaks"): there is no separate `verification_state` axis to drift. The observability payoff (design §18): the legacy world's scattered emit sites collapse to one — `applyEvent` is the single append point for the `pr_coordination_events` journal, and `stageOf` is the single stage taxonomy.

**Wiring status (updated 2026-07-03, Wave 11 + D-59c).** `project()` now has live consumers: `labelsOf` drives GitHub PR labels (W11-P2), the `session_index` mirror columns are written from the projection (W11-P1 → D-59c sole-write), `stageOf` stamps the transition observability event, and the `legacy-adapter` record feeds `divergence`/`backfill`. D-59c also made `project()` the sole `rich_status` writer for post-publish states (ACTIVE and TERMINAL) — `fsmDisplay` writes the status pill unconditionally at the same seam as `fsmMirror`. Still legacy-fed: Slack status surfaces. A `project()` change now moves labels/mirror-columns **and** the UI pill for post-publish states.

## Working on the FSM — checklist

1. **Reacting to a new signal** → add/extend a producer (`*-producer.ts`) that emits an FSM event; extend `transition.ts` + `guards.ts`. Never mutate lifecycle state outside `applyEvent`.
2. **Adding/writing a record field** → give it a complete writer set inside `applyEvent`'s CAS (design §4 is the per-field writer contract). Never write `pr_coordination` from a route/service directly.
3. **Changing what a surface shows** → extend `project()` / `answered-projection.ts` and add a projection test. Labels, PR-body stage, mirror columns, and the UI status pill (`rich_status`) for post-publish states are all projection-sourced (D-59c). Slack status surfaces are still legacy-fed.
4. **Touching a legacy review-loop path** → read the sweep ownership map first. Legacy machinery is deliberately retained (the FSM does not own every decision); gating or deleting it blindly can strand live sessions.
5. **Schema changes** → `pr_coordination` / `pr_coordination_events` follow the append-only migration rules ([database.md](database.md)).
6. **Verifying** → the pure `transition()` and `project()` are unit-testable without a sandbox (their totality is `tsc`-enforced); the live boundary needs actual Cycloid session evidence ([testing.md](testing.md#e2e-means-a-cycloid-session)).

## What is NOT the FSM's job (scope guards)

- **QA-internal liveness / heartbeats / death-detection** are the QA team's responsibility, out of scope for the spine (design §13/§14). The spine owns only the QA **contract**: one request in, exactly one run-scoped terminal verdict out, plus a coarse deadline backstop (explicitly _not_ a liveness signal). Do not re-home the ARC-1273 verification lock into the spine.
- **The DO event log / transcript** stays the DO's source of truth (session SQLite is the replay authority). The FSM is the source of truth for lifecycle **coordination state**, not for the raw event stream. See [what-is-cycloid.md](what-is-cycloid.md) and [lifecycle.md](lifecycle.md).

## Persistence, backfill, divergence

- **Store:** D1 `pr_coordination` (state, PK `session_id`; migration `0214`) + append-only `pr_coordination_events` (one row per committed transition; migration `0215`). Single-writer via an optimistic CAS on the `version` column (bounded retry on a lost CAS).
- **Genesis:** the `CREATED` row is inserted for every new session at the session-create funnel (`insertGenesisRecord`, `session/state.ts` → `genesis.ts`; unconditional, idempotent). Without it, `applyEvent` early-returns `no_record`.
- **Backfill:** pre-existing sessions are seeded via `POST /api/admin/fsm/backfill` (`routes/admin-fsm-backfill.ts` → `backfill-runner.ts`), admin-gated, idempotent (`dryRun` first; `rebaseline` rewrites only still-`version=0` rows), with a stale-session fence that freezes long-inactive sessions so post-flip `applyEvent` no-ops on them.
- **Divergence samplers (removed at D-60):** during the shadow rollout the samplers (in the `*/5` sweep) compared the spine row against an _independently_ legacy-derived state (`legacyAdapterRecord`, non-tautological) and fed the `arcanist.fsm.divergence` metric/monitor. They were the flip go/no-go substrate; with the flip complete they (and the metric/monitor) are deleted. The permanent soak signal is `arcanist.fsm.parity` (`parity-check.ts`, below).
- **The evidence gate (Section-G deletions).** Re-based from a calendar soak to evidence (Jag, 2026-07-02). Deletion PRs merged when ALL held: (1) prod `REVIEW → MERGE_READY` transitions observed and the T1 repair passes fired (`POST /api/admin/fsm/row7-repair`, both targets), with the `legacy=MERGE_READY/VERIFYING vs spine=REVIEW/NEEDS_YOU` divergence shapes collapsed; (2) the W11-G1 instruments clean — `fsm.sideeffect.failed`/`sink_failed` ≈ 0, `fsm.transition` `noop:unhandled` rate flat, volume-floor widget non-zero; (3) the non-tautological `arcanist.fsm.parity` check (`parity-check.ts` — spine vs the GitHub PR's own state + verifier-child outcomes) run over terminal sessions with zero unexplained / zero FSM-less-safe shapes (W11-G3 classification); (4) per-unit preconditions in the Wave-11 execution plan.
