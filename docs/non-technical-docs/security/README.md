# Cycloid Security Package

Vendor-agnostic source of truth for the security assurance materials Cycloid provides to prospects and customers conducting vendor security review (vendor onboarding, pilot security review, contractual exhibits, etc.).

The package is one consolidated document. Each section answers a common security-review ask.

## Layout

```
docs/non-technical-docs/security/
├── README.md                                  (this file)
├── _template/
│   ├── cycloid_letterhead.docx               source letterhead (copy of customer_templates/cycloid_letterhead.docx)
│   ├── cycloid_reference.docx                generated reference doc used by pandoc (regenerated by build-reference.sh)
│   ├── build-reference.sh                     produces cycloid_reference.docx by merging pandoc default styles into the letterhead
│   └── build.sh                               runs pandoc + post-processes the output
├── source/
│   └── cycloid-security-package.md           canonical markdown source
└── dist/                                      (gitignored)
    └── cycloid-security-package.docx         consolidated output
```

## How to build

```sh
docs/non-technical-docs/security/_template/build.sh
# or to a custom output dir:
docs/non-technical-docs/security/_template/build.sh /tmp/security-package-out
```

Requires `pandoc` on the PATH.

The pipeline runs pandoc against `cycloid_reference.docx` (the letterhead with pandoc's default style set grafted in) and then post-processes the docx to strip `<w:tblLayout w:type="fixed"/>` from every table. Without the post-process, Pages refuses to split tables across pages, which orphans every Section heading above a tall table.

If the letterhead changes or pandoc is upgraded enough to ship new defaults, regenerate the reference doc:

```sh
docs/non-technical-docs/security/_template/build-reference.sh
```

That script also strips `keepNext` / `keepLines` from every heading style and adds `pageBreakBefore` to Heading 1 so each Section starts on a fresh page.

## How to ship to a customer

1. Run the builder.
2. Copy `dist/cycloid-security-package.docx` to the customer's folder under `~/Documents/cycloid-docs/customer_templates/<customer>/`.
3. Apply per-customer edits only where a customer's review explicitly asks for something the standard version doesn't cover.

## What's deliberately not in this package

- **Pre-audit standalone policy PDFs** for privileged-access, secure SDLC, vuln management, BCP/DR, personnel security, endpoint security. The documented-and-attested form of each is a SOC 2 deliverable; producing parallel pre-audit copies creates version drift. See Section 11.
- **Penetration-test report.** Doesn't exist yet; commissioned alongside the SOC 2 audit cycle. See Section 9.
- **Customer-specific contractual artifacts** (NDAs, security-exhibit redlines, BAAs where applicable). Those live under `customer_templates/<customer>/` in the docs repo and, for OpenEvidence specifically, under `docs/non-technical-docs/openevidence/`.

## Open verification items (refresh before each delivery)

1. **GitHub App permission manifest (Section 6)** — reconcile against the live GitHub App settings page; the source is derived from repo grep.
2. **SOC 2 timeline (Section 9)** — confirm the audit kickoff and Type II target match the current engagement letter.
3. **Subprocessor list (Section 4)** — confirm DPA / BAA / contractual status entries match Provider's current vendor register.
4. **S3 region default (Sections 1 & 5)** — currently `us-east-1` per `services/archive.ts`; confirm matches production.
