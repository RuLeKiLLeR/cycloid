# Debugging runbook

Agent-facing, repo-wide. Use this to debug control-plane / session / review-loop / QA testing issues fast: a methodology, a symptom→code index, and the telemetry/log keys (plus their gotchas).

Complements [docs/codebase-map.md](codebase-map.md) (orientation) and [docs/debugging.md](debugging.md) (Datadog golden path, service names). Per-incident facts live in agent memory; this doc is the durable, whole-repo map.

## Methodology (evidence-first)

1. **State the failure class, not the symptom.** "RLA never handed off to QA testing" -> "the done-state -> QA Tester scheduler edge fires but the scheduler fails." Audit equivalent paths once found.
2. **Read the authoritative state, not assumptions.** PR state via `gh` (private repos: authenticated local `gh` only, never web). Session/DO state via telemetry. Confirm the head SHA the code is actually tracking before theorizing.
3. **Find the failing boundary in the multi-component chain.** Flow: webhook/cron → control-plane worker → session DO → service (scheduler/sweep) → child session (verifier) → bridge. Establish which boundary breaks with evidence at each side.
4. **Prefer telemetry for history; `wrangler tail` for the missing detail.** Structured events + spans are in Datadog. Control-plane/DO pino `warn`/`info` logs are **not** (logpush off) — the exact error string often lives only in a live tail.
5. **Confirm root cause before fixes.** Cite the datum that settles it; label what's still unverified. Distinguish "the attempt never happened" from "the attempt failed."

Worked example (2026-06-23 QA hand-off stall — illustrates the method; the `review-loop-status-comment.ts` status comment and the first-verdict QA gate cited below have since been removed (B1/#6998 + the CI-ladder cut), so this exact failure can no longer recur): PR `CLEAN` + status comment stuck "waiting on QA testing" -> `review-loop-status-comment.ts` maps that to epoch `ready` (gate held) -> gate is `isAwaitingFirstVerificationVerdict` (`review-loop-sweep.ts`), true forever while `verificationState` is null (`phase.ts`) -> DO `/session/review-loop/done-state` handler calls the scheduler on the edge, but `schedule_failed` 500s **before** persisting `done` / emitting `review_loop.settled` (`durable-object.ts`) — mode-split: shadow/off 500s before persist (sweep tick-retry re-drives), live persists first and never 500s (D17 sweep repair owns redelivery) -> `qa_tester.schedule.failed` re-fires every ~5 min (shadow/off) or settles on the repair pass (live) -> `wrangler tail` revealed the scheduler threw `No validated OpenAI key` (QA Tester inherits the parent Codex model but the parent ran on subscription auth; `verification-auto-scheduler.ts` -> `provider-credential-gate.ts`).

**Five sandbox-kill paths, often conflated** (architecture in [docs/sandbox-architecture.md](sandbox-architecture.md#e2b-sandbox-lifecycle)):

1. **Orphan reaper** — cron, kills _unreferenced_ running VMs (no live `session_index` row) older than `E2B_ORPHAN_REAPER_MIN_AGE_MS_DEFAULT` (10m; env override key `E2B_ORPHAN_REAPER_MIN_AGE_MS`, resolved by `getE2BOrphanReaperMinAgeMs`). `sandbox/e2b-orphan-reaper.ts`.
2. **Retention cleanup** — cron, terminates/pauses _referenced_ VMs whose lease/retention expired. `session/cleanup.ts`. (Reaper = unreferenced, cleanup = referenced — complementary, not redundant.) The same DO cleanup-run workflow is also invoked by the FSM on final-terminal sessions (reason `session_terminal`, see path 5).
3. **Heartbeat-liveness watchdog** — per-session DO alarm, marks the sandbox stopped and begins bounded fresh-sandbox retry (or terminalizes at the retry cap) after `SANDBOX_HEARTBEAT_LIVENESS_MS` (60s) without a bridge heartbeat. Clean-close reconnect grace and provider-alive deferral share the same 60s last-heartbeat budget; prompt/tool activity cannot extend it. `session/lifecycle/reducer.ts`.
4. **ARC-1248 liveness gate** — runs _inside_ the reaper's owner-guard (`applyReaperLivenessGate`): a 5-min heartbeat-staleness + K-consecutive-stale-sweep debounce (`SANDBOX_REAPER_LIVENESS_STALE_MS`, `SANDBOX_REAPER_ZOMBIE_STALE_SWEEPS`) that **protects/defers** a physically-running owned VM the bookkeeping reaper would otherwise kill. Fail-closed; kill switch `E2B_ORPHAN_REAPER_LIVENESS_GUARD`.
5. **FSM final-terminal reclaim** — event-driven, not cron. When a session reaches a FINAL terminal (`MERGED`/`CLOSED`/`SUPERSEDED`/`ARCHIVED`), the FSM `terminate_runtime` side-effect reclaims the runtime VM immediately (reason `session_terminal`) instead of parking it paused for the 72h retention window. Reuses the same DO cleanup-run workflow (`runE2BRuntimeCleanupViaSessionDO`) with reason-aware override. `session/fsm/live-side-effects.ts:terminateRuntimeExecutor`. Never fires on `user.stop → STOPPED` (STOPPED stays resumable).

A VM "dying" mid-session is usually (1)+(4) (reaper reclaim) or (3) (bridge went silent). Check `@source:reaper` or `@source:lifecycle` on the `runtime.terminate` to tell a reap from a watchdog teardown or FSM-driven terminal reclaim.

## Telemetry & log keys

- **Datadog is US5.** All endpoints/URLs use `https://us5.datadoghq.com`.
- **Two telemetry channels reach Datadog; pino does not.** `wrangler.toml` has `logpush=false`, so control-plane / SessionDO `logger.warn/info` (pino) lines are **not** in Datadog. Only:
  - **Structured events** via `postStructuredEventToDd` (`observability/events-exporter.ts`): `service:cycloid-control-plane`, `@_direct_post:true`, fields are **snake_case** top-level attributes — `@event`, `@session_id`, `@pr_url`, `@reason_code`, `@error`, etc. Query by `@event:<name>`; free-text misses them (message is empty/JSON).
  - **Spans** via `TRACE_QUEUE` (`service:cycloid-session-do` / `cycloid-control-plane`): route spans carry `@span.session.id` and `@span.do.route` (e.g. `do./session/review-loop/done-state`). Free-text on a UUID misses these — use `@span.session.id:<id>`.
- **Pino logs (the missing detail) → `wrangler tail`.** Fields are **camelCase** (`sessionId`, `msg`, `error`). Get them live:
  ```bash
  npx wrangler tail cycloid-control-plane-production --format json > tail.log
  # --search may NOT filter under --format json; post-filter the multi-line JSON with jq:
  jq -r 'select((.logs|tostring)|test("<session-id>")) | .logs[]?.message[]?' tail.log
  ```
  Tail is live-only (no history); the loop/cron you're chasing may need a few minutes to re-fire.
- **Event catalog** (all `service:cycloid-control-plane @_direct_post:true`; metrics in `infra/datadog-log-metrics.tf`, monitors in `infra/datadog-monitors.tf`):
  - `review_loop.epoch.completed` → `arcanist.review_loop.epoch_completed`
  - `review_loop.settled` → `arcanist.review_loop.settled` (`final_state`, `schedule_reason`) — emitted on done-state settle (commit-before-side-effects under live); also emitted from loud side-effect fan-out on terminal transitions. Absence on a shadow/off `schedule_failed` loop signals a hand-off that never completed.
  - `prompt_admit_decision` (review-loop turns) → `arcanist.review_loop.dispatch{dispatch_path:…,source_kind:…}` — counts review-loop prompt admits by dispatch path (`cold`/`live`/`resume_*`) and source kind. The "Review Loop & QA Tester" dashboard's Immediacy section shows cold-dispatch share and dispatch-path mix. Prewarm fires before each enqueue; a high cold-share means `warmSession` is not keeping runtimes live.
  - `review_loop.triage` → `arcanist.review_loop.triage{outcome:…}` (`outcome: used|fallback`, `reason` on fallback) — LLM triage outcome; fallback drives the deterministic whole-worklist prompt. Use the "Review Loop & QA Tester" dashboard's triage fallback-rate widget; there is no live fallback regression monitor right now.
  - `review_listening.dormant_count` — snapshot count of caught-up dormant `review_listening` sessions emitted once per sweep tick. Non-zero steady count confirms dormancy reduction is working; sudden rise flags a regression; persistent zero when sessions exist flags that dormancy never fires. Log-only drill-down (no metric group_by on `dormant_count`).
  - `qa_tester.run.completed` → `arcanist.qa_tester.run_completed` (`verdict`, `result`).
  - `qa_tester.schedule.failed` → `arcanist.qa_tester.schedule_failed` (`reason_code`) — the hand-off threw; carries `@error`/`@pr_url`/`@session_id`. Monitor the QA Tester scheduling failure alert.
  - `session.view.metrics` → `cycloid.session_view.*_ms` — latency decomposition for GET /api/sessions/:sessionId/view; metrics include `do_fetch_ms`, `assembly_ms`, `total_ms`, `do_build_ms`, `do_prompt_actor_profiles_ms`, `do_owner_actor_profile_ms`, `do_spine_done_mirror_ms`, `worker_actor_profiles_ms`, `worker_ui_lifecycle_stage_ms`, `worker_parent_metadata_wait_ms`, `assembly_cpu_ms`. Tagged `outcome` on worker segments for hit/fallback drill-down.
- **Reaper telemetry has a pino gap — confirm in `wrangler tail`, not just Datadog.** The orphan reaper runs in the cron `scheduled()` handler on `cycloid-control-plane`, but emits its reap/guard detail via **pino**: `logger.warn`/`logger.info` in `sandbox/e2b-orphan-reaper.ts` (`e2b_orphan_reaped`, `e2b_orphan_owner_guard_*`, `e2b_orphan_reap_failed`) and `this.log.warn`/`info` in `durable-object.ts` `logE2BOwnerGuardOutcome` (`sandbox.runtime.owner_guard`, carrying `decision`/`reason_code`/`liveness_guard_prevented_reap`). Per the pino rule above and `infra/cloudflare-logpush.tf` (`control_plane_worker_datadog` `enabled=false`), those lines are **not in Datadog** — read them with `wrangler tail`. The only reaper event that reaches Datadog is `e2b_orphan_reaper.swept` (`postStructuredEventToDd`), the per-sweep heartbeat. **Consequence:** the log-metrics `arcanist.e2b.orphan_reaped`, `arcanist.sandbox.reaper.liveness_protected`, and `arcanist.sandbox.reaper.zombie_reclaimed` (`infra/datadog-log-metrics.tf`) do **not** populate from prod as written; surfacing the liveness-guard prevalence on a dashboard needs those events direct-posted (same fix shape as the ARC-1273 watchdog metrics).

## Pulling private-repo + worker state

- **GitHub (private repos):** authenticated local `gh` CLI only — never browser/web fetch.
- **Worker logs:** `wrangler tail` (above). Historical control-plane data: Datadog. Requires `wrangler` OAuth with `workers_tail` scope.
- **Product inspection:** prod `https://app.trycycloid.com`, QA `https://qa.app.trycycloid.com`.
- **A session's exact prompt (any business, from a PR/branch/URL/UUID):** `bash scripts/debug/customer-session-prompt.sh <arg>`. D1 (`session_index`) maps a branch/PR back to a session id across businesses; the prompt text itself is only in Braintrust (project `cycloid`), keyed by `metadata.sessionId`, in the `prompt:p-N` span's `input.user`. Full procedure + gotchas: the `debug-customer-session` skill.
