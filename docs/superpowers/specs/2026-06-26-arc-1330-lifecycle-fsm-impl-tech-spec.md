## Context

Today a Cycloid session's post-PR life is coordinated by **6 state vocabularies, 4 overlapping locks, 3 disagreeing label lists**, and a cron that makes decisions. The failure modes are concrete and recurring: a silent stall at `session/durable-object.ts:7110-7235` (a `schedule_failed` returns **500 before persisting** the done-state, so the loop re-fires forever), stale verification verdicts merging unvalidated heads, stranded reviews, and "label says done / verdict says app-breaks" illegal states. ARC-1330 replaces all of it with **one finite state machine spanning session genesis → PR → CI → code-review → verification → merge-ready**, with a single-writer CAS, pure projections, and net code subtraction.

The **authoritative design is v7** (`docs/superpowers/specs/2026-06-26-arc-1330-lifecycle-fsm-v4-consolidated-design.md` — filename says v4, content is v7), with the **deletion tracker** and the **collapse-latency delta** (provenance) as companions. This file is the **implementation plan** — a maximally-atomic Graphite stack — not new design. The review cycle is closed; this is the tech-spec phase.

**Branch model (Jag, this session):** every small atomic PR targets a long-lived integration branch **`arc-1330-lifecycle-fsm`** (cut fresh off `origin/main`). Once the whole stack is merged into the feature branch and tested end-to-end there, **one big PR** merges the feature branch into `main`. The post-merge **flip + deletion** PRs (which depend on the live prod divergence metric) then go straight to `main` as small follow-ups.

> **Long-lived-branch policy.** The 4 build-stack migration files (`0206/0207/0208/0209`) are **renumber-at-integration placeholders** (see the INTEGRATION MERGE gate). Schedule a periodic `main → arc-1330-lifecycle-fsm` code merge (cadence: at least weekly, and before any Section E producer PR that wraps a hot file) so the final integration diff stays reviewable and the producers wrap current code. Section E wraps the hottest files (`durable-object.ts` ~15k ln, `prompt-queue`, `publish-service`, `webhooks/github`, `review-loop-sweep`) — keep those merges current.

## §17 underspecified items — resolutions (with recommendations)

- **§17-A run-identity (ABA) — BUILD `verification_run_id` + `verification_child_id`** _(decision 2)_. Monotonic counter on `pr_coordination`; incremented by `request_verification` (and re-stamped by `redispatch_verification`); passed to the verification child at spawn and **echoed on every `verification.*` verdict event**. Freshness = `event.run_id == record.verification_run_id`. The **killable child handle** is stored separately as `verification_child_id` (the verifier child-session id), set by the spawn side-effect; `kill_verification` resolves **the verdict's run** to its child via that handle, never the active run. Realization: add `verificationRunId` to the child-spawn input (`scheduleAutoVerificationAfterReviewLoopDone`) and to `VerifierTerminalResult`, echoed back through the `post_execution` handler. Rationale: the gate's stale-pass class (B4) is correctness-critical and the existing `verification_session_requests` PK is `(pr_url, head_sha)` — head-only identity, the ABA-vulnerable shape.
- **§17-B `no_inflight_epoch` read-source + `inc_ci_fix_rounds` anchor — model in-flight as a record field.** Add `in_flight_epoch_id TEXT` to `pr_coordination`, written **under the same CAS** as `dispatch_epoch`; `no_inflight_epoch := in_flight_epoch_id IS NULL`. Epoch terminals (`committed/replied/declined`) clear it in their CAS write. This makes `no_inflight_epoch` a **committed, same-`applyEvent`-visible** read, satisfying the FG-2 inc/reset mutual exclusion (a ciFix-dispatch transition reads `no_inflight_epoch=false`, so it can `inc` but not `reset` in one step). The `in_flight_epoch_id` **is** the `inc_ci_fix_rounds` idempotency anchor: `inc` fires only on the NULL→non-null transition; the actual epoch spawn is the after-commit side-effect keyed by that id, so a retried spawn never double-counts.
- **§17-C `review.item_ready` producer — the `release_queued_reviews` action.** After commit, `release_queued_reviews` enqueues exactly one internal `review.item_ready{item_id}` back into `applyEvent` per released worklist item; the `REVIEW` self-loop consumes `review.item_ready / dispatch_epoch`. This guarantees released/injected items re-run the cascade and get an epoch — no wedged `caught_up`.
- **§17-D MERGE_READY⇄REVIEW flap (cost) — lifetime reopen cap.** Add `merge_ready_reopen_count INTEGER` (NOT reset on MERGE_READY entry). When a red-CI re-open would push it past `MAX_MERGE_READY_REOPENS` (default 5), route to `NEEDS_YOU{ci_flapping}` (decision 5a — distinct reason).

**Two grounded must-builds the design under-specified (now in-scope):** the **disposition store** (decision 1) and **`prompt_intends_change`** derivation (projection-only, net-new; reuse `observedPromptProgress`, no new LLM call — decision 5c).

## Observability (folded in — design §18, lifecycle dashboard substrate)

**Single substrate, single emit site.** The future dashboard ("enter a `session_id` → current stage + per-stage durations + the per-reviewer / per-RLA-cycle narrative") is a thin reader over the `pr_coordination_events` log. Every **handled** transition (incl. self-loops, §8) already appends to that log inside `applyEvent`; observability **enriches that one append** and **emits from that one site**. Producers attach a typed metadata payload to the event they already raise — they do not emit telemetry. Net-new, additive, **non-gating**: reads no guard, changes no edge.

**Two new columns on `pr_coordination_events`** (PR 3): `metadata TEXT` (JSON, nullable — the typed payload), `dwell_ms INTEGER` (`now − state_entered_at` at transition = time since the previous event; `Σ dwell_ms GROUP BY from_state` = total time in a state; order by `version`).

**`EventMetadata` discriminated union** (PR 4, verification-named), one variant per `FsmEvent`. Load-bearing slices:

- `review.received` → `{ reviewer_kind: bot|human, reviewer_id, review_source_id, actionable }` (`reviewer_id` = GitHub app-slug/login = **Greptile/Strix/Copilot/human**, from the webhook author).
- `epoch.{committed,replied,declined,blocked}` → `{ epoch_id, epoch_trigger, source_ids[], head_before, head_after, disposition }` (the **RLA cycle** — dispatch ts ≈ "RLA started", `epoch.committed`/`head.changed` ts ≈ "RLA published", `dwell_ms` between = RLA working time).
- `head.changed|noop_changed` → `{ head_sha, prev_head_sha }`; `verification.{pass,skipped,app_breaks,stopped,failed,run_limit}` → `{ verification_run_id, verdict, head_sha }`; `ci.signal` → `{ ci_state }`; `→NEEDS_YOU`/`→FAILED` → `{ blocked_reason|failure_reason }`; `postexec.done` → `{ has_changes, prompt_intends_change }`.
- **Invariant O1:** metadata is observability-only — never read by a guard/cascade/transition (the spine reads typed record fields). Keeps `transition()` pure; the schema evolves additively without a soundness re-review.

**Centralized emit** (PR 34, in `applyEvent` after commit, best-effort/try-caught off the legacy path — reuse the shadow-error isolation): one structured DD event via `postStructuredEventToDd` (`observability/events-exporter.ts:128`) `{ session_id, business_id, version, from, to, event, dwell_ms, stage_from, stage_to, …metadata }` + metrics `arcanist.fsm.transition` (count) and `arcanist.fsm.stage_dwell_ms` (distribution) + the unhandled-event (`noop=unhandled`) DD emit. **Invariant O2:** a thrown emit never blocks the CAS commit. The new `cycloid.fsm.*` metrics are **outside** the `verification → qa` rename surface (deletion-tracker note) — do not fold/rename.

**Stage axis = `project().stage_section`** (PR 28–30 expose a pure `stageOf(record)` for the timeline query — no new taxonomy).

**Read surface** (new **PR 27A**): pure `getSessionTimeline(sessionId) → { current_stage, events[], stage_durations }` over `pr_coordination_events` + a reconstruction test (the lossless-contract proof). Internal admin route + UI + Terraform fleet-dwell widget are **post-merge follow-ups** (out of this stack).
