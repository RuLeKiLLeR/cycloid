## 0. What this consolidates, and how it was produced

v3 set the right _shape_ (QA is the single functional gate, Intent is a background non-gating observer, no manual-PR) but is a thin contract delta that left the load-bearing write-path and several edges under-specified. This doc folds in:

- **Two independent multi-agent reviews** of the original spec (11 element reviewers + 6 whole-machine sweeps each, adversarial 2-lens verification) → 48 confirmed defects.
- **A cross-check of those 48 against v3+lean** → 18 already fixed, 3 obsoleted by the restructure, **27 still-present/partial** carried here.
- **A fresh whole-machine sweep of the v3 restructure** → 38 new defects, dominated by one cluster: **QA emitting `MERGE_READY` directly bypasses the merge-ready conjunction**. Fixed structurally here (§9: all QA outcomes return through `REVIEW`; `REVIEW.caught_up` is the _sole_ emitter of `MERGE_READY`).

Every non-obvious decision below cites the finding it closes (`F#` = original review, `S#` = v3 sweep).

## 1. Shape

```
            ┌─ observes (read-only, fire-and-forget) ─▶ ⟦INTENT · bg⟧ ─ mismatch ─▶ Slack alert + non-blocking PR annotation
            │   (spawned at FINALIZING when has_diff; reaped on any terminal)
CGA ──(has_diff)──▶ PUBLISHING ──▶ REVIEW ⇄ ⟦QA⟧
                                     ▲   │       │
                                     │   │ caught_up[code_changed & under_cap] / request_qa
                                     │   └───────┘
                                     │   qa.pass/skipped/app_breaks  (ALL return here; record_qa, re-evaluate dispatch)
                                     │
                  caught_up[¬code_changed ∧ qa_pass ∧ qa_fresh ∧ ci_green] ──▶ MERGE_READY ★ (sole emitter)
                  caught_up[else] ──▶ NEEDS_YOU ⚡ / dispatch ciFix / re-QA   (total, never silent)

⟦QA⟧ = black-box child session (other team); emits one terminal event into the spine; the spine owns head-stamping/caps/deadlines/teardown.
⟦INTENT·bg⟧ = background child session; read-only on the CGA diff; never gates; reaped by the spine on every terminal.
```

The macro pipeline is **`REVIEW` (CI-fix + code-review on one worklist) → QA**. QA is the final gate, but it does **not** transition to `MERGE_READY` itself — it returns to `REVIEW`, and the one guarded `REVIEW.caught_up` edge is the single door to `MERGE_READY` (S: conjunction-bypass cluster).

## 3. States

Kind: `initial` / `active` / `wait` / `contract` (active, externally-owned agent) / `terminal-*`.

| State                            | Group    | Kind             | Meaning                                                                                 | Deadline         |
| -------------------------------- | -------- | ---------------- | --------------------------------------------------------------------------------------- | ---------------- |
| `CREATED`                        | genesis  | initial          | Row created (keyed `session_id`), no sandbox.                                           | spawn            |
| `PROVISIONING`                   | genesis  | active           | E2B sandbox spawning.                                                                   | spawn            |
| `GENERATING`                     | codegen  | active           | CGA running; multi-prompt self-loop.                                                    | exec             |
| `AWAITING_INPUT`                 | codegen  | wait             | CGA asked the user a question.                                                          | abandon          |

| `REVIEW`                         | post-pr  | active           | Combined CI-fix + code-review + QA-finding convergence core; triages CI failures and reviews on ONE worklist. | review           |
| `QA`                             | post-pr  | **contract**     | QA child running the app @head.                                                         | qa               |
| `MERGE_READY`                    | terminal | terminal-success | Reviews drained ∧ CI green ∧ QA pass @head. Re-openable. Signal-only.                   | (long reconcile) |

| `MERGED` / `CLOSED` / `ARCHIVED` | terminal | terminal-final   | —                                                                                       | —                |

`INTENT` is **not** a spine state (§13). `QA` is the only `contract` state.

> **`MERGE_READY` is not deadline-less.** It carries a long _reconcile_ deadline (D17) so a dropped `pr.merged`/`pr.closed` webhook can't leave a session "Ready" forever (S). The cron poll normally fires first.

```
MERGE_READY := state == REVIEW                 // only emitter is the REVIEW.caught_up edge (D10)
            ∧ caught_up(H)                       // all reviews addressed
            ∧ qa_pass ∧ qa_fresh                 // approving QA, head-stamped (D4/D5)
            ∧ ci_green(H)                         // live-read; a red PR is never ready
            ∧ ¬code_changed_since_qa             // nothing changed since the approving QA
```

**`caught_up` recompute set — pinned here, not deferred (B6/F35).** `applyEvent` recomputes `caught_up` on each of:

1. every epoch terminal: `epoch.{committed,replied,declined}`,
2. every `review.received`,
3. the reviewer-settled (no-show) timer,
4. a `ci_green` live-read flip (`ci.signal(green|absent)` / CI re-poll),
5. **entry to `REVIEW` from the QA-verdict return (`record_qa`)** — closes the happy-path stall (B6: a clean QA pass returning to an empty review queue must evaluate the cascade on arrival, else the sole `MERGE_READY` door never opens), and
6. **entry to `REVIEW` from a `NEEDS_YOU`/`MERGE_READY` re-open** — the triggering review is consumed by the re-open, so the cascade must be evaluated on arrival, not on a later incidental event.

This is the **recompute-completeness** class: any transition that changes a cascade input (`code_changed`, `ci_green`, dispositions, `qa_*`) or re-enters `REVIEW` must re-run the cascade. The same class covers **SF5**: a ciFix epoch completing green in `REVIEW` must re-evaluate the cascade (the `ci_green` rows), not drop a green signal that arrived mid-epoch.

> **Ordering (no race with `inject_findings`/`register_review`).** `caught_up` is a first-class **internal event** (§5), so the cascade is a **separate `applyEvent`** from the transition that enters `REVIEW` (§8 applies one decision per event). The entering transition's disposition writes (`inject_findings` on `app_breaks`, `register_review` on a re-open) are **committed before** the `caught_up` evaluation reads the disposition store — the recompute observes the registered undispositioned items, so an `app_breaks` arrival cannot fire row 6 (`qa_unresolved`) and a re-open cannot bounce straight to row 7 (`MERGE_READY`) before the just-injected/registered item is counted (closes the SF16/B6 ordering concern). **This is why §7 places the `inject_findings`/`register_review` worklist registration in the committed bucket (a), not the after-commit bucket (b) (FG-5):** the registration must be durable before any `caught_up` read, so it cannot be a deferred side-effect. _(Implementer note: register the items in the entering transition's committed write so no `caught_up` read ever sees a pre-registration snapshot.)_

## 7. Actions

Two buckets — this split is the single-writer fix (F1/F14/F19); §8 enforces it.

**(a) Record-field writes — folded into the one CAS `UPDATE … SET … WHERE version = ?` — plus the worklist registrations that must be durable before the next `caught_up` read (FG-5):**

- `advance_head{head_sha := event head}` — live PR head.
- `init_record{pr_url, head_sha := event.pr_head, code_changed_since_qa:=true, qa_runs:=0, ci_fix_rounds:=0}` (B5). _(Nit: `prompt_intends_change` is **not** written here — set at `FINALIZING`, §9, before publish.)_
- `record_qa(verdict){qa_verdict, qa_head_sha := head_sha (the accepted live head), code_changed_since_qa:=false; qa_runs:=0 only on pass|skipped (B1 — app_breaks preserves qa_runs)}`. Stamps `qa_head_sha` from the **live head** at accept, reached only after the verdict-arrival freshness guard passed (B4); never from `request_qa`.
- `request_qa{qa_runs += 1, qa_run_head := head_sha, arm qa deadline}` — **only** the `REVIEW.caught_up → QA` dispatch (B1). Does **not** stamp `qa_head_sha` (B4).
- `redispatch_qa{qa_run_head := head_sha, arm qa deadline}` — in-QA re-run (stale verdict / in-QA real `head.changed`); **no `qa_runs` change** (B1), no `qa_head_sha` stamp (B4).
- `set_code_changed{code_changed_since_qa:=true}` · `clear_qa{qa_verdict:=none, qa_head_sha:=none}` · `restamp_qa{keep verdict, qa_head_sha := head_sha}` (used on content-noop in `REVIEW`/`MERGE_READY`/`NEEDS_YOU`).
- `inc_ci_fix_rounds{ci_fix_rounds += 1}` (rides each `dispatch_epoch(ciFix)`; in-flight idempotency anchor for the commit→dispatch window pinned to §17, SS2); `reset_ci_fix_rounds{ci_fix_rounds:=0}` is the **conditional universal post-action** above (B7/FG-2 — §15 inv 11) — every committed post-PR transition resulting in `ci_green ∧ no_inflight_epoch` clears it, so `epoch.replied`/`epoch.declined` (no code change) also clear it when they complete into a green quiescent state.
- `clear_block{blocked_reason:=none}` · `arm_deadline{state_entered_at, deadline_at}` · `set blocked_reason / failure_reason (clear on FAILED→PROVISIONING) / stop_mode / pre_stop_state / update_branch_queued_at` · `set intent_child_id` (pre-allocated at `FINALIZING`, SF3).
- **`register_review(undispositioned)`** {records a received review as an undispositioned actionable worklist item — used on the `MERGE_READY`/`NEEDS_YOU` re-open so the triggering review keeps `caught_up` false until addressed, Defect 3} and **`inject_findings`** {register injected `app_breaks` items as undispositioned actionable worklist items, SF16} — **worklist registrations committed with the entering transition (FG-5), before any `caught_up` recompute reads them (§6 ordering)**, not deferred after-commit side-effects. _(The worklist is the epoch table, §13; the requirement is durability-before-read — committed in the same `applyEvent` as the entering transition, ahead of the separate `caught_up` event.)_

**(b) External side-effects — dispatched after commit (idempotent, version-keyed; redelivered by the cleaner, D17):**
`spawn_sandbox · dispatch_prompt · open_pr · spawn_intent_bg · reap_intent_bg · kill_qa(**run-scoped** child teardown — targets a specific QA run handle; the ghost-discard edge targets the **verdict's** run, never the active `qa*run_head` run, FG-1) · spawn QA child · dispatch_epoch · resolve_owned_threads · release_queued_reviews · emit_settle · loud()=notify_user+notify_arcdev+emit_dd · project()` *(`register_review`/`inject_findings` worklist registrations moved to bucket (a), FG-5/§6.)\_

**Universal post-actions on every transition:** `bump_version`, `append_event_log`, `arm_deadline` (bucket a), `project` (bucket b).

> **Conditional universal post-action — `reset_ci_fix_rounds` (FG-2, hardened).** On **every committed post-PR transition whose resulting state satisfies `ci_green ∧ no_inflight_epoch`**, also set `ci_fix_rounds := 0`. Making the reset a post-action (not a per-edge action) is **structural**: it cannot be missed by an un-annotated edge. In particular it fires on **all three** epoch terminals — `epoch.committed` **and** `epoch.replied`/`epoch.declined` (a review answered or a suggestion declined reaches a quiescent green with **no** code change) — closing the gap a per-terminal enumeration left (the FG-2 review-refuter trace). It reads the live `ci_green`/`no_inflight_epoch` of the **resulting** state, so it fires synchronously **on** the epoch-terminal transition (no wait for a re-poll, no transient window). It can never coincide with `inc_ci_fix_rounds`, which only rides a `¬ci_green` red signal. Per-edge `reset_ci_fix_rounds` mentions elsewhere (the `REVIEW` green `ci.signal` self-loop, cascade rows 6/7) are **illustrative instances** of this one rule, not independent mechanisms (§15 inv 11).

> `request_qa`/`redispatch_qa` are split (F14): the `qa_runs`/`qa_run_head`/`arm-deadline` writes are CAS field-writes; only the QA-child _spawn_ is post-commit, keyed by the per-head idempotency anchor (D15) so an infra-retried spawn doesn't double-increment `qa_runs` or spawn a duplicate child. A late verdict from a killed run is rejected by the verdict-arrival freshness guard (`event.head_sha == qa_run_head`, B4), so `kill_qa` being best-effort cannot admit a stale `pass`.

## 8. The write path (single writer)

```
applyEvent(session_id, event):
  rec       = SELECT * FROM pr_coordination WHERE session_id = ?
  decision  = transition(rec.state, event, guards(rec, event))     // pure; null = no-op (logged)
  if !decision: log_noop; return
  changed   = UPDATE pr_coordination
                 SET state = decision.to,
                     version = version + 1,
                     state_entered_at = now, deadline_at = now + deadline_class(decision.to),   // arm_deadline
                     <ALL decision.field_writes>                    // bucket (a): head_sha, qa_*, code_changed_since_qa, blocked_reason, …
                 WHERE session_id = ? AND version = rec.version     // CAS — the single-writer guarantee
  if changed == 0: re-read; re-evaluate idempotently               // lost the race → event may now be a no-op
  INSERT INTO pr_coordination_events (session_id, version, from, to, event, at, actor)
  dispatch(decision.side_effects)                                  // bucket (b), AFTER commit
```

- The CAS `WHERE version = ?` is the **only** DB concurrency primitive; it replaces the TTL lock, the per-head request-table claim, the epoch reservation CAS, and the done-state mirror (deletion tracker areas 1 & 4). **It does not replace** the GitHub-comment lease or epoch crash-recovery (D15, §14).
- All `field_writes` ride the CAS, so a guard on the next event can never read a torn/stale field (F1/F19). A crash before `dispatch` leaves committed state whose side-effects the cleaner redelivers (D17) — no silent drop (F36).
- `pr_coordination_events` is the one activity log; it also carries settle-dedup (replaces the DO `review_loop_settled_last` key).
- **`log_noop` has two distinct senses — do not conflate (FG-2 depends on it):** (i) the write-path `if !decision: log_noop; return` above is an **unhandled** event (no matching edge → `transition` returns null) → it logs and **returns early, running NO post-actions**; (ii) a §9 **handled self-loop** written `event / log_noop` is a real decision (`to = same state`, no field write) → it **bumps version and RUNS the universal post-actions**. The FG-2 green `ci.signal(green|absent)` self-loops are sense (ii) — committed self-loops **precisely so** the `reset_ci_fix_rounds` post-action runs; implementing them as sense (i) would silently reopen FG-2. (Tech spec: make the handled-self-loop-vs-unhandled-event distinction explicit in `transition`.)

**Entry to `REVIEW` — the CI-settled epoch-1 trigger + eager dispatch (v7 changes 2/3).** `REVIEW` triages CI failures and actionable reviews on **one worklist** (the disposition store; reviews are registered as actionable **on arrival**, not parked in a separate queue — there is **no CI-first queue**). The loop has exactly **two intentional waits** (§15 inv 6):

- **Epoch 1 fires on CI-settled, not CI-green.** The first epoch in `REVIEW` dispatches when `reduceCiState(head) ≠ pending` (all checks terminal, incl. `absent` for no-CI repos), carrying whatever is actionable at that moment (CI failures **plus** any reviews already present); reviews not yet in form a second wave. It is **not** gated on `ci_green`. **v8 (latency): epoch 1 is split by cohort — when an actionable review is _already present_ at REVIEW entry, epoch 1 dispatches _eagerly_ on `no_inflight_epoch ∧ actionable` (the same rule as epochs 2..n), NOT waiting for CI-settled; the CI-settled trigger is kept ONLY for the no-actionable-review cohort (where there is nothing to do but wait for CI to surface failures — discrete failing checks there still dispatch via the reactive `ci.signal(failing)` self-loop). The eager epoch bundles any `ci.signal(failing)` checks already surfaced at dispatch, so most batching value is kept; the only residual red-path cost is one extra ciFix epoch for checks that settle red _after_ dispatch — bounded by `ci_fix_rounds`, never a correctness issue (the merge-ready gate still requires `ci_green`). Closes the trace finding that a fast-bot review sat held for `(ci_settle − review_arrival)` on the CI-green happy path.** _(Late-check guard: key on **required** checks / a short debounce, not "every check object currently present," so a late-registered run can't false-fire epoch 1 — pinned to §17. No-CI repos: `absent` is cron-paced via the re-poll, D17.)_ If CI settles **green with nothing else actionable** (no failures, no reviews yet), epoch 1 does not fire — the PR moves toward the first-contact no-show window / `caught_up`.
- **After epoch 1, dispatch is eager.** The only gate on the next epoch is `no_inflight_epoch ∧ actionable`; `ci_green` is **never** a dispatch precondition — it is required only at the merge-ready gate, re-checked there. CI is validated **reactively per pushed head** via the `ci.signal(failing)` self-loops below; a head advance supersedes a stale CI result. Cost: a red pushed head may burn one extra ciFix epoch (bounded by `ci_fix_rounds → NEEDS_YOU(ci_fix_exhausted)`) — never a correctness issue, since the merge-ready gate still requires `ci_green`.

**Review pass (`REVIEW`)** — in-place self-loops: `review.received | review.item_ready / dispatch_epoch`; `epoch.committed / advance_head, set_code_changed, disposition(fixed), resolve_owned_threads`; `epoch.replied / disposition(replied), resolve_owned_threads`; `epoch.declined / disposition(declined)` _(**FG-2**: all three epoch terminals — including `replied`/`declined`, which a review answer/decline reaches with **no** code change — clear `ci_fix_rounds` via the **conditional universal post-action** (§7) when they complete into `ci_green ∧ no_inflight_epoch`; the reset is **not** enumerated per-terminal, so it cannot be missed — closing the FG-2 review-refuter gap)_; `ci.signal(failing)[no_inflight_epoch ∧ under_ci_fix_cap] / dispatch_epoch(ciFix), inc_ci_fix_rounds`; `ci.signal(failing)[in_flight_epoch] / log_noop` _(don't double-dispatch or double-count while an epoch runs — same guard as cascade row 3, which gates the identical action on `caught_up`'s `no in-flight epoch`. **Note (FG-4 boundary):** this reactive self-loop fires on a **discrete failing check** (`ci.signal(failing)` = a real red exists), intentionally distinct from the cascade's **aggregate** `ci_pending` live-read — a genuinely failed check warrants ciFix even while other checks still run; the `no_inflight_epoch` guard prevents per-check inflation, so it neither false-trips `ci_fix_exhausted` nor strands)_; `ci.signal(failing)[no_inflight_epoch ∧ ¬under_ci_fix_cap] → NEEDS_YOU(ci_fix_exhausted) / set blocked_reason, loud()`; `ci.signal(green|absent)[no_inflight_epoch] / log_noop` _(**FG-2**: a green observed in `REVIEW` clears `ci_fix_rounds` via the conditional universal post-action (§7) — even while reviews are outstanding (`caught_up=false`) or `code_changed` — so a later red flap can't trip `ci_fix_exhausted` on a stale carry; an explicit self-loop (not a dropped signal) precisely so the post-action runs)_; `ci.signal(green|absent)[in_flight_epoch] / log_noop` _(no reset yet (`no_inflight_epoch` false); the green is re-observed when the in-flight epoch completes via **any** of `epoch.committed`/`replied`/`declined`, where the post-action then fires — closing the replied/declined gap)_; `head.changed / advance_head, set_code_changed, clear_qa`; `head.noop_changed[¬code_changed_since_qa] / advance_head, restamp_qa`; `head.noop_changed[code_changed_since_qa] / advance_head` _(N4: both branches advance the head; `restamp_qa` rides only the `¬code_changed` branch — if code already changed the verdict is stale and re-QA is forced anyway, so don't restamp. Two formal branches, total over `head.noop_changed`)_.

The `caught_up` cascade — **ordered and total** over `(code_changed × ci_green × qa_pass × qa_fresh × under_qa_cap × under_ci_fix_cap)` (D10/D11/S/B7); pairwise-disjoint guards, evaluated top-down:

1. `caught_up[code_changed_since_qa ∧ under_qa_cap] → QA / request_qa` _(request_qa: `qa_runs += 1`, `qa_run_head := head_sha`, allocate the active run's identity — the only run-burning dispatch, B1/FG-1; §17)_
2. `caught_up[code_changed_since_qa ∧ ¬under_qa_cap] → NEEDS_YOU(qa_noconverge) / set blocked_reason, loud()` _(the **legitimate** non-convergence terminal — real head changes keep re-entering this cascade and burning `qa_runs` via `request_qa` until the cap trips; **not** the FG-1 ghost path, which is discarded in `QA` and never reaches here)_
3. `caught_up[¬code_changed_since_qa ∧ ci_red ∧ under_ci_fix_cap] → REVIEW / dispatch_epoch(ciFix), inc_ci_fix_rounds` _(CI **failing** since QA; bounded by `ci_fix_rounds`, B7. **FG-4:** gated on `ci_red` (`reduceCiState=failing`), **not** `¬ci_green` — `¬ci_green` also covers `ci_pending`, and dispatching ciFix against still-running CI is wrong)_
4. `caught_up[¬code_changed_since_qa ∧ ci_red ∧ ¬under_ci_fix_cap] → NEEDS_YOU(ci_fix_exhausted) / set blocked_reason, loud()` _(ciFix loop exhausted on a genuine red, B7/FG-4)_
5. `caught_up[¬code_changed_since_qa ∧ ci_pending] → REVIEW / log_noop` _(**FG-4 — the wait cell:** CI is still **running** (`reduceCiState=pending`, which dominates) — neither green nor failing. **Wait** for the next `ci.signal`/CI re-poll; do **not** dispatch ciFix and do **not** trip `ci_fix_exhausted`. A permanently-pending CI is caught by the `{REVIEW}` review-stuck deadline (§10), not the ciFix cap)_
6. `caught_up[¬code_changed_since_qa ∧ ci_green ∧ ¬qa_pass] → NEEDS_YOU(qa_unresolved) / set blocked_reason, reset_ci_fix_rounds, loud()`
7. `caught_up[¬code_changed_since_qa ∧ ci_green ∧ qa_pass ∧ qa_fresh] → MERGE_READY / reset_ci_fix_rounds, emit_settle, notify_user` **(sole MERGE_READY emitter, D10)**
8. `caught_up[else] → NEEDS_YOU(internal_inconsistency) / set blocked_reason, loud()` _(the loud catch-all; the only residual cell is `¬code_changed ∧ ci_green ∧ qa_pass ∧ ¬qa_fresh`, unreachable by the **directional** implication `(¬code_changed ∧ qa_pass) ⟹ qa_fresh` — never the false biconditional, SF8/D11; wired loud, never silent)_

> **Totality/determinism note (B7/FG-4).** The CI live-read is **ternary** on the `¬code_changed` branch: `reduceCiState(head)` partitions exhaustively & disjointly into `ci_green` (`{green, absent}`), `ci_red` (`failing`), `ci_pending` (`pending`). Rows 3/4 fire only on `ci_red` (split on `under_ci_fix_cap`); row 5 is the `ci_pending` **wait** cell; rows 6/7 are the `ci_green` cells; row 8 is the loud `[else]` catch-all whose only residual cell is `ci_green ∧ qa_pass ∧ ¬qa_fresh` (directional implication, D11). The cascade stays **total** (the three CI predicates exhaust `reduceCiState`'s four return values; rows 1/2 exhaust `code_changed`) and **deterministic** (pairwise-disjoint guards) — the reviewer's base `(code_changed × ci × qa_pass × qa_fresh × under_qa_cap × under_ci_fix_cap)` surface is preserved with `ci` now 3-valued on the `¬code_changed` branch, and `under_ci_fix_cap` a clean 2-way split inside the `ci_red` rows (3/4) only. **`reset_ci_fix_rounds` rides the `ci_green`-true rows (6/7)** and — per FG-2 — **every other committed post-PR transition resulting in `ci_green ∧ no_inflight_epoch`** (the conditional universal post-action, §7 — all three epoch terminals incl. `replied`/`declined`, plus the `REVIEW` green self-loop), so the counter never carries a stale value out of the ciFix loop; the re-open edges also reset it so a `NEEDS_YOU(ci_fix_exhausted)` retrigger gets a fresh CI-fix budget.

- `REVIEW — epoch.blocked → NEEDS_YOU / set blocked_reason{epoch.blocked(owner_approval)→owner_approval}, loud()` _(post-code-review owner_approval is the **only** owner-approval path, P1/D8; deterministic — no competing pre-publish edge)_

**QA contract (`QA`)** — in-place: `head.changed / advance_head, kill_qa, redispatch_qa` _(real head change → re-run @ new head; `redispatch_qa` does **not** burn a run, B1; `qa_run_head := new head`)_; `head.noop_changed / advance_head, restamp_qa` _(content-identical push: `qa_run_head` is **unchanged** so the in-flight verdict stays fresh, and `restamp_qa` advances `qa_head_sha` to track the live head — no spurious re-run, SF9)_; `review.received / queue_review`; `ci.signal / no-op` _(ci_green is re-checked at the MERGE_READY gate via the REVIEW cascade, so a red flip during QA cannot reach READY — S)_. **Every exit runs `kill_qa`.**

Verdict-arrival freshness (B4/FG-1) is **run-scoped**: a verdict belongs to a specific QA run, and only a verdict from the **active** run (the one `qa_run_head`/`qa_run_id` currently identifies) may drive a transition. `qa.{pass,skipped,app_breaks}` carry the run they were computed against (`event.head_sha`, equivalently a `qa_run_id` token); the verdict is **fresh** iff it matches the active run (`event.head_sha == qa_run_head`). A killed/superseded run's late verdict matches **no** active run ⇒ it is a **ghost** and is **discarded** (FG-1 edge below) — never recorded, never re-dispatched, never consulting the cap, never terminating. Because every in-QA real `head.changed` runs `redispatch_qa` (so a live `qa_run_head` child always exists), the ghost can always be safely dropped and the live run left to report. `record_qa` then stamps `qa_head_sha := head_sha` (live) on the **fresh** accept, so the cascade's `qa_fresh` is true at accept.

- `QA — qa.pass[event.head_sha == qa_run_head] → REVIEW / record_qa(pass), release_queued_reviews, kill_qa` _(fresh verdict from the active run)_
- `QA — qa.skipped[event.head_sha == qa_run_head] → REVIEW / record_qa(skipped), release_queued_reviews, kill_qa`
- `QA — qa.app_breaks[event.head_sha == qa_run_head] → REVIEW / record_qa(app_breaks), inject_findings, release_queued_reviews, kill_qa` _(record_qa preserves `qa_runs` on app_breaks, B1)_
- `QA — qa.{pass,skipped,app_breaks}[event.head_sha ≠ qa_run_head] → QA / log_noop, kill_qa(verdict's run)` _(**FG-1 — ghost discard:** a verdict that does not match the active run is a late emission from a **superseded (already-killed) run**. Every in-QA real `head.changed` already ran `redispatch_qa`, so a live `qa_run_head` child exists and will report. **Discard** the ghost: do **not** redispatch, do **not** consult `under_qa_cap`, do **not** terminate. `kill_qa` is **run-scoped to the verdict's run** (idempotent re-kill of the already-dead child) and **never** touches the live `qa_run_head` run. This removes the false `NEEDS_YOU(qa_noconverge)` terminal that abandoned a live run whose newest code could merge. Genuine non-convergence still terminates via cascade row 2, B1)_
- `QA — qa.run_limit → NEEDS_YOU(qa_run_limit) / set blocked_reason, release_queued_reviews, loud(), kill_qa`
- `QA — qa.stopped | qa.failed → NEEDS_YOU(qa_stopped) / set blocked_reason, release_queued_reviews, loud(), kill_qa` _(QA infra failure / contract violation is post-publish → `NEEDS_YOU`, re-openable; **not** `FAILED`, which re-spawns codegen on an open PR — S. The `qa` deadline backstop (§10) routes the same way, P2.)_

> **Queue-drain rule — the transient QA queue only (v7 change 1 removed the one-time CI-first queue):** with the collapse, reviews are registered as actionable **on arrival** in `REVIEW` and dispatched eagerly — they are never parked. The **only** remaining queue is the **transient QA hold**: while `QA` owns the head a code-fix epoch can't dispatch, so items arriving during `QA` accumulate in the disposition store and dispatch is **re-evaluated on every QA exit**. `release_queued_reviews` (now "re-evaluate dispatch") fires on **every QA exit** (the three `REVIEW`-returning verdicts, `qa.run_limit`/`qa.stopped`/`qa.failed`, the `{QA}` deadline — the FG-1 ghost-discard is a `QA→QA` `log_noop` self-loop, **not** an exit, so it correctly does not drain; the live `qa_run_head` run's eventual exit drains) **and every `NEEDS_YOU → REVIEW` re-open** (where the released reviews are actually dispatched). The `MERGE_READY → REVIEW` re-opens **omit** the drain because the queue is provably empty at `MERGE_READY` entry (a review can never rest queued in `MERGE_READY`: non-actionable → `log_noop`, actionable → re-open), so the "every re-open" rule holds vacuously there (nit). Because registered-but-undispositioned reviews count as actionable, re-evaluating on QA exit guarantees `caught_up` can converge — no review is stranded in any non-`QA` resting state. `MERGE_READY` stays the strict conjunction (D10).

**Terminal re-entry**

- `MERGE_READY — review.received[actionable] → REVIEW / register_review(undispositioned), dispatch_epoch, reset qa_runs` _(the triggering actionable review is **registered as undispositioned and dispatched** on re-open — it is not merely "consumed", so `caught_up` stays false (the open epoch + the undispositioned item) and the session cannot bounce straight back to `MERGE_READY` and drop the review (Defect 3 / B6). `ci_fix_rounds` is already 0 — reset at the green that produced READY)_
- `MERGE_READY — review.received[¬actionable] → MERGE_READY / log_noop` _(an informational / already-resolved review does not re-open a Ready PR — coverage of the non-actionable case)_
- `MERGE_READY — head.changed → REVIEW / advance_head, set_code_changed, clear_qa, reset qa_runs`
- `MERGE_READY — head.noop_changed → MERGE_READY / advance_head, restamp_qa` _(restore lean, S)_
- `MERGE_READY — ci.signal(failing) → REVIEW / dispatch_epoch(ciFix), inc_ci_fix_rounds` _(restore lean L97 — red CI after Ready must re-open; **no `set_code_changed`** — a flaky CI flip with no new commit must not force a spurious re-QA on identical code, SF7. `ci_fix_rounds` was reset to 0 at the row-7 green that produced READY, so `inc`→1 starts a fresh ciFix budget.)_
- `NEEDS_YOU — review.received[actionable] → REVIEW / clear_block, release_queued_reviews, register_review(undispositioned), dispatch_epoch, reset qa_runs, reset_ci_fix_rounds` _(dispatch the triggering review; `release_queued_reviews` (re-evaluate dispatch) drains any transient QA queue accumulated before the block so `caught_up` can converge — B2 wedge fix, VERIFY-confirmed)_
- `NEEDS_YOU — user.retrigger → REVIEW / clear_block, release_queued_reviews, set_code_changed, reset qa_runs, reset_ci_fix_rounds` _(the **sole** manual retrigger edge **back into the review loop** — `FAILED → PROVISIONING` (§9) is the other `user.retrigger` edge, but it re-spawns codegen pre-publish, not the review loop (nit); owner_approval is post-review, routes here, no competing `→ PUBLISHING` edge, so deterministic, B3/P1; `release_queued_reviews` unwedges any stranded transient QA queue, B2; resetting `ci_fix_rounds` gives a `NEEDS_YOU(ci_fix_exhausted)` retrigger a fresh CI-fix budget)_
- `NEEDS_YOU — review.received[¬actionable] → NEEDS_YOU / log_noop` _(an informational review does not re-open a blocked session or re-arm the caps — coverage of the non-actionable case; the `[actionable]` guard above prevents a non-actionable review from resetting `qa_runs`/`ci_fix_rounds`, addressing the coverage-lens "no actionable guard" finding)_
- `NEEDS_YOU — head.changed → REVIEW / advance_head, set_code_changed, clear_qa, clear_block, release_queued_reviews, reset qa_runs, reset_ci_fix_rounds`
- `NEEDS_YOU — head.noop_changed → NEEDS_YOU / advance_head, restamp_qa` (S)
- `FAILED — user.retrigger → PROVISIONING / re-spawn, clear failure_reason` _(N6 — clear the stale reason so a re-spawned session doesn't carry it through `PROVISIONING`/`GENERATING`)_

## 10. Cross-cutting (restated in v4 vocabulary)

The original "inherited from lean" reference silently named deleted/renamed states (`AWAITING_MANUAL_PR`, `VERIFYING`, `BLOCKED`, `READY_TO_MERGE`); restated here (S):

- **Hard-failure → `FAILED`** (loud, `set failure_reason`). Group `{CREATED, PROVISIONING, GENERATING, FINALIZING, PUBLISHING}` on `sandbox.death | sandbox.liveness_expired | sandbox.spawn_failed | prompt.max_duration_exceeded | prompt.terminal{error}`. **`AWAITING_INPUT` is NOT in this group** — its sandbox death is `→ STOPPED(resumable)` (F4). _(N3: event is `prompt.terminal{error}` per §5, not `prompt.error`.)_
- **Wait-state sandbox death.** `AWAITING_INPUT — sandbox.death | sandbox.liveness_expired → STOPPED(stop_mode=resumable, pre_stop_state=AWAITING_INPUT)`.
- **PR closed out → terminal-final.** Post-publish group `{REVIEW, QA, MERGE_READY, NEEDS_YOU, STOPPED}` on `pr.merged → MERGED` / `pr.closed → CLOSED`. **`PUBLISHING` race (N9):** a `pr.merged`/`pr.closed` webhook for the just-opened PR can arrive before the `publish.pr_opened` transport event — handle `PUBLISHING — pr.closed → CLOSED` / `pr.merged → MERGED` so the session can't proceed to `REVIEW` on an already-closed PR (defensive; the per-head idempotency anchor dedups the late `publish.pr_opened`).
- **Stop / archive.** `user.stop → STOPPED` (all non-terminal). `session.archived → ARCHIVED` for non-terminal **and** the non-final terminals `{ANSWERED_NO_PR, MERGE_READY, NEEDS_YOU, STOPPED, FAILED}` (F26).
- **Deadlines.** `deadline_exceeded`: `{CREATED,PROVISIONING}→FAILED(spawn_timeout) / set failure_reason, loud()`; `{GENERATING,FINALIZING,PUBLISHING}→FAILED(execution_timeout) / set failure_reason, loud()`; `{AWAITING_INPUT}→STOPPED(resumable, no blocked_reason)`; `{REVIEW}→NEEDS_YOU(review_stuck) / set blocked_reason, release_queued_reviews, loud()` _(drains the transient QA queue on the `REVIEW` timeout so it isn't stranded — B2; loud per D1)_; `{QA}→NEEDS_YOU(qa_stopped) / set blocked_reason, release_queued_reviews, kill_qa, loud()` _(B2 drain + teardown; this is the **coarse contract backstop** for a QA child that emitted no terminal event — **explicitly not a liveness signal**, P2; loud per D1)_; `{MERGE_READY}→` cron reconcile (not a terminal — re-poll PR state, D17). _(Nit: the deadline `→FAILED`/`→NEEDS_YOU` edges carry `loud()` like their §9 per-edge terminal twins, D1.)_
- **Resume (phase-aware).** `STOPPED — user.input[resumable] →` codegen-phase + dead sandbox → `PROVISIONING / spawn_sandbox`; codegen-phase + live sandbox → re-arm; **review-phase `pre_stop_state ∈ {REVIEW, QA}`** → re-enter that state and re-arm watch; a `QA` resume re-dispatches via **`redispatch_qa` (no `qa_runs` burn)** — resuming the interrupted run is not the `REVIEW→QA` dispatch that `request_qa` counts, so a stop/resume cycle must not consume a QA round (the PR exists; no codegen prompt); **publish-phase `pre_stop_state ∈ {FINALIZING, PUBLISHING}`** → re-enter that phase (the diff/branch exists — re-run post-exec / retry `open_pr`; do **not** discard it by re-spawning codegen); only a dead sandbox with an unpushed diff falls back to `PROVISIONING` (SF12 — closes the non-total resume map). (S — renamed from the lean's `VERIFYING`.)
- **Child teardown.** `reap_intent_bg` is a **universal terminal action** — it fires on **every** terminal entry (`MERGED/CLOSED/ANSWERED_NO_PR/STOPPED/FAILED/NEEDS_YOU/ARCHIVED`, and `MERGE_READY`), so a background Intent child + its stale "mismatch" alert can never leak past ship/cancel/block (SF4/D2/D7). Additionally, if a QA child is live, every QA exit and every terminal runs `kill_qa` (§13).

## 11. Single-writer & illegal-state guarantees (the bugs this kills)

- **No blocking state between `CREATED` and `PUBLISHING` (P1).** The genesis→publish half has **no** `NEEDS_YOU` / owner-approval / sensitive-path gate. The only non-forward exits before the PR exists are hard `FAILED` (infra/agent death) and `STOPPED` (user). Owner-approval, if used, is a **post-code-review** `epoch.blocked(owner_approval) → NEEDS_YOU` reason only — it never blocks PR creation. _(Testable: no transition from `{CREATED,PROVISIONING,GENERATING,FINALIZING,PUBLISHING}` targets `NEEDS_YOU`.)_
- **Illegal combos unrepresentable:** there is no separate `verification_state` label axis — every label is a projection of `(state, qa_verdict)` (§12), so "label says done, verdict says app_breaks" cannot exist (F40). `qa_verdict=app_breaks ∧ state=MERGE_READY` is unrepresentable because the only `MERGE_READY` emitter requires `qa_pass` (D10). `blocked_reason`/`stop_mode`/`failure_reason` are `none` outside their owning state (D14/N6).
- **No torn writes:** every field rides the CAS (§8).
- **No silent rest:** the `caught_up` cascade is total with a loud catch-all (D11); every active/wait state has a `deadline_at` writer (D12 arm_deadline) and a `deadline_exceeded` target.
- **Recompute-completeness (B6/SF5):** any transition that changes a cascade input or re-enters `REVIEW` (incl. the `record_qa` return and the `NEEDS_YOU`/`MERGE_READY` re-opens) re-runs `caught_up`; a ciFix epoch completing green in `REVIEW` re-evaluates the cascade. No load-bearing recompute is left to an incidental later event.

## 13. Contracts — `QA` (gate) and `INTENT` (background)

**`QA`** — child session (`agent_role="qa"`). Spine enters from the `REVIEW.caught_up[code_changed ∧ under_qa_cap]` edge, owns head-stamping/caps/deadlines, and **tears the child down on every exit (`kill_qa`)** so no QA child outlives its run (F37/S). **`kill_qa` is run-scoped** — it targets a specific QA run handle; a late verdict from a **superseded** run is a **ghost** discarded in `QA` (FG-1, §9), and its teardown targets that dead run, **never** the live `qa_run_head` run. Agent→spine events: `qa.pass/skipped/app_breaks` (each carrying `head_sha`), `qa.stopped/failed/run_limit` (§9). The agent owns only the judgment.

> **⚠️ QA-internal liveness / heartbeat / death-detection is OUT OF SCOPE by decision (P2).** This spec owns the QA **contract only** — the events in/out (`request_qa` → exactly one of `qa.pass | qa.skipped | qa.app_breaks | qa.stopped | qa.failed | qa.run_limit`), head-stamping, caps, and the deadline backstop. The contract **requires** the QA child to emit exactly one terminal event **including on its own failure/death**. QA-internal liveness fidelity (extend-on-progress, heartbeats, sound death-proof) is the **QA team's responsibility** and must **not** be built into the spine, and the ARC-1273 verification-lock heartbeat must **not** be re-homed as a spine mechanism. The spine's `qa` deadline (§10) is a **coarse backstop** for a contract-violating child that emits nothing (`→ NEEDS_YOU(qa_stopped)`) — **it is explicitly not a liveness signal.** Future agents: do not spend effort re-building QA-internal liveness into the spine.

**`INTENT`** — fire-and-forget background child (`agent_role="intent"`), spawned at `FINALIZING` on `has_diff` (so it observes every diff-producing turn, not only published ones — S/SF3). It reads the diff read-only and, on mismatch, posts a **Slack alert** + drives the non-blocking `intent-mismatch:⚠` PR annotation (§12). It emits **no spine events**; caps/freshness/loops do not apply. The spine retains exactly one field, `intent_child_id` (pre-allocated at `FINALIZING` so the CAS write is synchronous, SF3), and `reap_intent_bg` is a **universal terminal action** (every terminal incl. `NEEDS_YOU`/`ANSWERED_NO_PR`/pre-publish `FAILED`/`STOPPED`, SF4/D2/D7) so a background child + its stale "mismatch" alert cannot leak past ship/cancel/block. Emit a Datadog metric for intent-child duration/leak.

> **Review disposition store + `epoch.declined` producer (decided here, not deferred — SF15).** Per-item dispositions (`fixed`/`replied`/`declined`) are recorded on the **epoch worklist** (extend it; not a new side table). `epoch.declined` is produced by **triage-with-basis** — a classification that the item needs no code change, plus the agent's reasoned reply — **not** an unchecked agent self-signal. This closes the soundness hole where a fix agent could self-decline real reviews to reach `MERGE_READY`. `inject_findings` registers injected `app_breaks` items as **undispositioned actionable** items on the same worklist, so `caught_up` stays false until the agent fixes them — preventing a premature `NEEDS_YOU(qa_unresolved)` immediately after `app_breaks` (SF16). The exact disposition-store columns remain a tech-spec detail; the **producer** and **store shape** are pinned here.

> If a future iteration wants Intent to gate again, it re-enters as a `contract` state with edges back into the spine — out of scope here.

## 14. What is KEPT, not folded (anti-over-deletion guards)

The single-writer CAS replaces the _DB-row_ concurrency mechanisms — but the following must survive, or the fold reintroduces a bug (F33/F34/F43, D15). The deletion tracker marks these **KEEP**.

**Structural concurrency KEEPs (the CAS does not cover these):**

1. **Comment posting/edit lease** (`review-loop-status-comment-db.ts`, migration **0120** — _not_ the dead 0186). The version CAS guards the DB row, not the GitHub comment API; without the lease the duplicate/clobbered-comment race returns when the cron reconcile and a webhook `applyEvent` both edit the comment.
2. **Epoch crash-recovery** — the lease-reclaim path (or an explicit statement that `arm_deadline → NEEDS_YOU` is the accepted loud give-up) and the transient-failure retry budget. The CAS gives mutual exclusion, not liveness.
3. **Per-head QA-spawn idempotency anchor**, decoupled from `qa_runs++`, so an infra-retried external spawn doesn't burn the cap.

## 15. Invariants

1. Single writer: all field mutations via `applyEvent`'s `UPDATE … WHERE version=?` (§8). _(Testable: no field write outside the CAS path; §4 enumerates the complete per-field writer set, SF1.)_
2. Side-effects dispatched after commit; redelivered by the cleaner (no rollback-on-side-effect, no silent drop).
3. Labels/stage/FE/phase are pure projections of `(state, record)`, **total** over every state (incl. `ARCHIVED`, N8) and over the closed `blocked_reason` enum (§12, SF10).
4. `MERGE_READY` has exactly one **entering edge from another state** (the `REVIEW.caught_up` emitter, D10) — plus its own `head.noop_changed` self-loop; its conjunction (§6) holds in-state (N7 — "exactly one in-edge" was literally false given the self-loop).
5. Every active state has a `deadline_at`; every wait state a long abandon deadline; no silent waits.
6. **No CI-first queue (removed in v7); the two-waits rule (SF17).** The one-time CI-first gate and its review queue are **gone** — reviews are registered as actionable **on arrival** in `REVIEW` and dispatched eagerly; CI is validated reactively per pushed head and re-checked only at the merge-ready gate. **The only transient hold is the QA hold:** while `QA` owns the head, code-fix epochs can't dispatch (a dispatch would move the head and invalidate the run), so items arriving during `QA` accumulate in the disposition store and dispatch is **re-evaluated on every QA exit** (and on the `NEEDS_YOU → REVIEW` re-opens). **The two intentional waits, and only these:** (a) **CI-settled before epoch 1** (`reduceCiState ≠ pending`, incl. `absent`) — **v8: only for the no-actionable-review cohort; when a review is already actionable, epoch 1 is eager (§9), so wait (a) does not apply** — and (b) the **first-contact no-show window** before the first `caught_up = true` (a per-PR latch on a per-session DO alarm, §B4/DE-3) — **v8: per-reviewer-kind, armed at `init_record`; the human window is 0 (optimistic + re-open), so wait (b) binds only on a silent _bot_**. Everything else is eager — no cron tick, no CI re-confirmation between epochs, no re-review wait. _(Testable: no review rests queued in any resting `REVIEW`/`MERGE_READY`/`NEEDS_YOU` state; the only queue is the QA-transient one, drained on every QA exit; the loop waits at most twice on the happy path.)_
7. `qa_fresh := qa_head_sha == head_sha` (cascade); verdict-arrival freshness is **run-scoped** — a verdict drives a transition iff it belongs to the active run (`event.head_sha == qa_run_head`, equivalently a `qa_run_id` token; §9, B4/FG-1, see inv 10); `head_sha` is initialized at publish (B5) and advances on every commit/head-change.
8. `qa_runs` bounds **consecutive failed QA rounds** — incremented only by `request_qa` (the `REVIEW→QA` dispatch), preserved on `qa.app_breaks`, reset only on `pass`/`skipped` and re-open (D13/B1). `ci_fix_rounds` bounds **consecutive CI-fix rounds** and resets on **every observed `ci_green ∧ no_inflight_epoch` in any post-PR state** (B7/FG-2, see inv 11). Both caps trip to `NEEDS_YOU`, never an unbounded loop.
9. No QA or Intent child outlives the session (`kill_qa` on every QA exit/terminal; `reap_intent_bg` is a universal terminal action, §13).
10. **QA verdicts are run-scoped (FG-1).** A verdict drives a transition iff it belongs to the **active** QA run; a verdict from a **superseded** run is a ghost and is **discarded** (`log_noop`) — never recorded, never re-dispatched, never consulting `under_qa_cap`, never terminating. `kill_qa` and verdict-matching target the **verdict's** run, **never** the active `qa_run_head` run. _(The run-identity realization — `qa_run_head` head-match vs a monotonic `qa_run_id` token that also closes the `H→H′→H` ABA hole — is pinned to §17.)_
11. **`ci_fix_rounds` resets on every observed `ci_green ∧ no_inflight_epoch` in any post-PR state (FG-2).** Realized as a **conditional universal post-action** (§7): every committed post-PR transition whose resulting state satisfies `ci_green ∧ no_inflight_epoch` clears the counter — so the reset is **structural** and **cannot be missed by an un-annotated edge**. In particular `epoch.replied`/`epoch.declined` (which reach a quiescent green with no code change) clear it too — the gap a per-terminal enumeration left (caught by the FG-2 review-refuter). It fires synchronously on the terminal transition (no re-poll wait, no transient window) and never coincides with `inc_ci_fix_rounds` (which only rides a `¬ci_green` red signal). Per-edge `reset_ci_fix_rounds` mentions (the `REVIEW` green self-loop, cascade rows 6/7) are illustrative instances of this one rule. *(Testable: no `ci_fix_rounds` > 0 survives any transition into a state where `ci_green ∧ no_inflight_epoch` holds.)\_

**Durable-execution invariants (DE-1..DE-5, v7).** Durable execution is realized on the **existing DO + D1 substrate — no new framework** (no Temporal / CF Workflows): the event log (`pr_coordination_events`) is the journal, `transition()` is the deterministic replay function, the single-writer CAS is the durable versioned state, commit-before-side-effects + cron redelivery (D17) is at-least-once idempotent side-effects, and DO alarms are the durable timers.

12. **DE-1 (event-driven).** Every external signal (CI / review / head / QA webhook) drives `applyEvent` **immediately**. The happy path **never** requires a `*/5` cron tick to advance; cron is a backstop for **dropped** webhooks only.
13. **DE-2 (immediate in-process side-effects).** Side-effects dispatch in-process right after the CAS commit (spawn sandbox / dispatch epoch / request QA). Cron redelivery is the **crash** backstop, not the delivery path.
14. **DE-3 (alarms, not cron, for happy-path timers).** The first-contact no-show window and all state deadlines are **per-session DO alarms** firing precisely at T — not the coarse `*/5` sweep. Cron keeps only **cross-session reconciles** (dropped-webhook merge/close poll, absent-CI re-poll, loud-signal redelivery — D17).
15. **DE-4 (parallel dispatch).** Independent side-effects on a commit fire concurrently.
16. **DE-5 (durability licenses aggression).** Because every eager/optimistic step is committed-before-acting, idempotent (version-keyed), and crash-resumable, the latency aggression (eager dispatch, optimistic `MERGE_READY`, the no-show latch) cannot cost correctness — a crash mid-dispatch resumes from the journal, a redelivered side-effect dedups, an optimistic `MERGE_READY` re-opens.

## 18. Observability (lifecycle dashboard substrate)

> **Status:** additive / non-gating addendum (2026-06-27). Does **not** reopen the closed soundness review — it adds an observability layer over the existing event log, touching no guard, edge, cascade input, or transition decision. Folded into the tech-spec PR stack (§18.6).

**Goal.** From a `session_id`, reconstruct the full lifecycle — ordered events with timestamps, the actor/detail at each step, and time spent in each stage — so a future internal dashboard ("enter a session ID → current stage + per-stage durations + the reviewer/RLA narrative: prompt started, published, Greptile commented, RLA started, republished, reviewer commented again, …, published finally") is a thin reader over D1.

**Principle — instrument once, at the choke point.** `applyEvent` (§8) is the single writer; every **handled** transition (incl. self-loops, sense-ii `log_noop`) already bumps `version` and appends to `pr_coordination_events`. Observability **enriches that one append** and **emits from that one site**. Producers do not emit telemetry; they only attach a typed metadata payload to the event they already raise. This is the structural payoff of the FSM: the legacy world's scattered emit sites collapse to one.

### 18.1 Event-log enrichment

`pr_coordination_events` (the §8 activity log) gains two columns:

| Column     | Type                  | Meaning                                                                                                                                                          |
| ---------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `metadata` | TEXT (JSON, nullable) | the typed per-event payload (§18.2) — the who/what (reviewer identity, epoch/cycle, head, verdict, reason). **Observability-only.**                              |
| `dwell_ms` | INTEGER               | `now − rec.state_entered_at` at transition time = **time since the previous event**. `applyEvent` already reads `state_entered_at` before the CAS (§8), so this is free. |

Because `state_entered_at` re-arms on **every** transition (§4, incl. self-loops), `dwell_ms` is the inter-event gap and aggregates cleanly:

- **total time in a state** = `Σ dwell_ms GROUP BY from_state` over a visit span;
- **sub-stage breakdown** (waiting-on-reviewer vs RLA-working) = `Σ dwell_ms GROUP BY (from_state, event[, metadata])`;
- **ordering** = `ORDER BY version` (monotonic per session);
- **multiple visits** to the same state (repeated `REVIEW` cycles) segment at the `from_state ≠ to_state` boundaries.

**Unhandled events** (§8 sense-i: no matching edge → early return, **no append**) are deliberately not written to D1 (the log stays a record of committed transitions) — but "an event arrived and the FSM ignored it" is a primary debugging question, so `applyEvent` emits those to **Datadog only**, tagged `noop=unhandled`, best-effort, off the critical path. (Handled `log_noop` self-loops — e.g. the FG-1 ghost-discard `QA→QA` — already append.)

### 18.2 Per-event metadata contract

A typed `EventMetadata` discriminated union mirrors `FsmEvent` (one variant per §5 event); each producer fills its slice. Load-bearing variants (others minimal — timestamps suffice):

- `review.received` → `{ reviewer_kind: bot|human, reviewer_id, review_source_id, actionable }` — `reviewer_id` is the GitHub app-slug / login (**Greptile vs Strix vs Copilot vs a human login**); the webhook producer already has it.
- `epoch.{committed,replied,declined,blocked}` → `{ epoch_id, epoch_trigger, source_ids[], head_before, head_after, disposition }` — the **RLA cycle**: the dispatching transition's timestamp ≈ "RLA started," the `epoch.committed` / subsequent `head.changed` ≈ "RLA published," the `dwell_ms` between = RLA working time.
- `head.changed | head.noop_changed` → `{ head_sha, prev_head_sha }`.
- `qa.{pass,skipped,app_breaks,stopped,failed,run_limit}` → `{ qa_run_id, verdict, head_sha }`.
- `ci.signal` → `{ ci_state: green|failing|absent|pending }`.
- every `→NEEDS_YOU` / `→FAILED` edge → `{ blocked_reason | failure_reason }`.
- `postexec.done` → `{ has_diff, prompt_intends_change }`.
- genesis / `sandbox.*` / `prompt.*` → minimal.

**Invariant O1 — metadata is observability-only.** No guard, cascade input, or transition decision may read `metadata`; the spine reads only the typed record fields (§4). This keeps `transition()` pure and lets the metadata schema evolve additively without a soundness re-review.

### 18.3 Stage taxonomy — reuse `project()`

The dashboard's coarse "what stage" axis **is** `project(record).stage_section` (§12: "Fixing CI" / "Addressing reviews" / "Testing the app" / "Ready for human review & merge ✓" / "Blocked — needs you: <reason>"). No new taxonomy. The timeline query maps each event's `from_state` (+ the `qa_verdict`/`blocked_reason` at that version) through a pure `stageOf(record)` helper and sums `dwell_ms`. Two axes fall out: **stage** (coarse — the dwell chart) and **activity** (fine — the event rows + metadata narrative).

### 18.4 Centralized emission

After the CAS commit + the `pr_coordination_events` INSERT, `applyEvent` emits (best-effort, try/caught, off the critical path — same isolation as the shadow-error path, §16 PR3):

- one **structured DD event** via `postStructuredEventToDd` (`observability/events-exporter.ts`): `{ session_id, business_id, version, from, to, event, dwell_ms, stage_from, stage_to, …flattened metadata }`;
- two **metrics**: `arcanist.fsm.transition` (count; tags `from,to,event,reviewer_id`) and `arcanist.fsm.stage_dwell_ms` (distribution; tag `stage`).

D1 `pr_coordination_events` is the **per-session source of truth** (drill-down); DD carries **fleet aggregates** (reviewer response latency, RLA cycle time, per-stage dwell distributions, stuck-stage monitors). A DD/emit failure never blocks `applyEvent` (O2).

### 18.5 Read surface

A pure DAO query `getSessionTimeline(session_id) → { current_stage, events[], stage_durations }` over `pr_coordination_events` (`ORDER BY version`), `stage_durations` summing `dwell_ms` through `stageOf`. **In scope (this stack):** the query fn + a **reconstruction test** that replays a real session's event log into the full timeline — the build-to-verify harness proving the metadata contract is lossless (the signal that the dashboard is buildable). **Follow-up (post-merge):** the internal admin route + UI page; a Terraform fleet-dwell dashboard widget (US5, existing module pattern).
